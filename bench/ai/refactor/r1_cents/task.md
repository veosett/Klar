Change the shop invoice program so that every money amount is an Int number of cents instead of a Float number of dollars.

- `catalog`: the field `price: Float` of `Item` becomes `price_cents: Int`. `make_item` takes `price_cents: Int` and still rejects a price that is not positive (message `invalid price for NAME`). `default_catalog` keeps its prices (Widget $3.50, Gadget $12.50, Gizmo $49.99, Cable $7.25, Case $24.00 = 350, 1250, 4999, 725, 2400 cents). `sorted_by_price`, `cheapest` and `catalog_text` work on `price_cents`.
- `money`: `format_amount` takes cents and returns the same text as before: `1250` -> `$12.50`, `5` -> `$0.05`, `-250` -> `-$2.50`, no thousands separator (`123456` -> `$1234.56`). `parse_amount` returns cents (Int), not dollars: `12.5` -> 1250, `12` -> 1200, `$3.99` -> 399, `  $0.05 ` -> 5. Valid text is optional surrounding spaces, an optional leading `$`, digits, and optionally a `.` followed by 1 or 2 digits. Anything else (`12.345`, `abc`, empty, `-1`, `1.2.3`, `.5`, `5.`) fails with the message `invalid amount: TEXT` (TEXT is the text as given). `round2` is no longer needed.
- `cart`: `line_total`, `subtotal`, `discount`, `tax`, `total` and `free_shipping_gap` return Int cents. The constant `FREE_SHIPPING_MIN` keeps its name and becomes 5000 (an Int; it was 50.0 dollars). Discount codes and quantities are unchanged: `discount_percent` still returns whole percents (SAVE10 = 10, WELCOME5 = 5, VIP15 = 15, HALF = 50) and the tax rate argument `rate_bp` is still an Int in basis points (825 = 8.25%).
- Rounding: `discount` is the exact value subtotal * percent / 100, rounded to the nearest cent, an exact half cent rounds up. `tax` is the exact value (subtotal - discount) * rate_bp / 10000 (tax is computed on the subtotal after the discount), rounded the same way. `total` = subtotal - discount + tax. Do not use Float arithmetic for this: the results must be exact.
- Rounding examples (amounts in cents): 5% of 1050 = 52.5 -> 53; 5% of 990 = 49.5 -> 50; 10% of 1004 = 100.4 -> 100; 10% of 1005 = 100.5 -> 101; 50% of 1001 = 500.5 -> 501; 8.25% tax on 1000 = 82.5 -> 83; 7.25% tax on 200 = 14.5 -> 15 (not 14); 8.25% tax on 997 = 82.2525 -> 82; 5% tax on 1010 = 50.5 -> 51; 10% tax on 1001 after a 50% discount (taxable 500) = 50.
- `free_shipping_gap` = `FREE_SHIPPING_MIN` - (subtotal - discount) in cents, but 0 when that amount is at least `FREE_SHIPPING_MIN`.
- `receipt`: `line_text`, `render` and `summary` produce exactly the same text as before for the same prices, e.g. `2 x Widget @ $3.50 = $7.00`, `Subtotal: $19.50`, `Discount (SAVE10): -$1.95`, `Tax: $1.45`, `Total: $19.00`, `Add $32.45 more for free shipping` (or `Free shipping`), `3 items, total $19.00`.
- Function names, parameter order, error messages and all other behaviour stay as they are.
