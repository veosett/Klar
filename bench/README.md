# Бенчмарки Klar

Одни и те же 6 алгоритмов написаны на Klar, C, C++, Rust, Go, Java, JavaScript и Python (`programs/<задача>/`).
Klar измеряется в трёх вариантах:

| колонка | что это |
|---|---|
| `klar` | **нативный компилятор** Klar → x86-64 (по умолчанию для `klar run`) |
| `klar-py` | запасной бэкенд Klar → байткод Python (`klar run --py`) |
| `klar-interp` | эталонный интерпретатор (`klar run --interp`) |

## Методика

* Каждая программа сама меряет время вычислений (`now_ns()` / `clock_gettime` / `performance.now()` …) и печатает
  `time_ms=`. Поэтому запуск процесса, JIT/JVM-прогрев и компиляция **не входят** в основное число; полное время
  процесса (wall-clock) — во второй таблице отчёта.
* Лучший результат из N запусков (`--repeat`, по умолчанию 3).
* Результаты всех языков сверяются (`result=`): отчёт помечает расхождение.
* Компилируемые языки: `gcc -O2`, `g++ -O2 -std=c++17` (идиоматичный C++: `std::vector`, `std::string`, алгоритмы STL), `rustc -O`, `go build`; Klar — `klar build` (с оптимизатором).

```
python bench/run_bench.py                       # все задачи, все найденные языки
python bench/run_bench.py -b fib loop -l klar c # выборочно
python bench/run_bench.py --repeat 5 --name my-pc
```
Отчёт пишется в `bench/results/<имя>.md` и `.json`.

## Задачи

| задача | что нагружает |
|---|---|
| `fib` | рекурсивный `fib(25)`: вызовы функций (≈250 тыс.) |
| `loop` | 300 тыс. итераций `total = (total + i*i) % 1000007`: целочисленная арифметика |
| `primes` | перебор делителей для чисел < 30 000: деление, ветвления, вызовы |
| `mandelbrot` | 120×60 точек, ≤50 итераций: Float |
| `collections` | `range(0, 200000).map(...).filter(...).sort()`, сумма, медиана: лямбды, списки, сортировка |
| `strings` | 100 тыс. строк `"item{i}"`, `join`, `split`, `filter(ends_with)`: строки и память |

## Результаты: ПК пользователя (Intel Core i5-8400, Linux VM, 2 vCPU), Klar 0.3

Время вычислений, мс, меньше — лучше (`user-pc-a/b/c.md`):

| задача | C -O2 | C++ -O2* | Rust -O* | **Klar** | Java 21 | JS (Node 22) | Python 3.10 | klar-py | klar-interp |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| fib | 0,157 | 0,154 | 0,237 | **1,1** | 0,649 | 2,3 | 18,6 | 18,5 | 1 695 |
| loop | 0,984 | 0,994 | 0,992 | **1,3** | 5,0 | 6,4 | 41,6 | 46,4 | 1 843 |
| primes | 1,9 | 2,0 | 0,939 | **3,6** | 4,9 | 2,9 | 23,9 | 35,5 | 2 035 |
| mandelbrot | 0,384 | 0,401 | 0,360 | **1,1** | 3,7 | 5,2 | 21,9 | 23,6 | 1 654 |
| collections | 5,1 | 6,0 | 3,0 | **10,0** | 37,7 | 43,1 | 39,3 | 65,6 | 1 219 |
| strings | 11,6 | 32,5 | 20,6 | **19,9** | 72,7 | 36,3 | 28,5 | 51,6 | 695 |

\* C++ и Rust измерены отдельным запуском (`user-pc-d.md`), когда машина была заметно нагружена: строковые
задачи у них могли получиться медленнее, чем на свободной машине.

* Klar быстрее Python в **1,4–32 раза**, в 1,3–7 раз медленнее C.
* Klar быстрее Java и Node.js на 4 из 6 задач (на коротких прогонах JIT не успевает разогреться — это честно
  для типичной программы, написанной ИИ, но на долгих вычислениях JIT догоняет).
* С запуском процесса: исполняемый файл Klar стартует за ~1–2 мс (как C), Python — ~50 мс, JVM — ~550 мс.

Klar быстрее Java и Node.js на всех шести задачах, обгоняет Go на `collections` и `strings`; на `loop`, `primes`
и `mandelbrot` он в 1,2–1,4 раза медленнее C. Самый большой разрыв — вызовы функций (`fib`, ~6× от C): пролог,
проверка глубины и передача аргументов через стек.
