# Модель угроз: агент запускает недоверенный код

ROADMAP, пункт 24. Сценарий: языковая модель пишет программу на Klar, а агент её запускает — через `klar run
--allow`, `klar dev`, `klar test` или MCP-сервер `klar mcp`. Код модели считается недоверенным: он может ошибаться и
может пытаться выйти за разрешённое (из-за ошибки или из-за атаки через промпт, например текстом в прочитанном
файле).

Что защищается:
- файлы вне разрешённых каталогов;
- другие программы;
- секреты в окружении;
- время и память машины.

Ниже — каждая угроза, что с ней сейчас и какой тест это проверяет. Статус: ✅ закрыто · ⚠️ открыто, есть обход ·
📌 так задумано (граница модели).

| # | Угроза | Статус | Как закрыто или что делать | Тест |
|---|---|---|---|---|
| T1 | **Выход из `fs:DIR` по символической ссылке.** В разрешённом каталоге лежит ссылка `data/link → /`, программа читает `data/link/etc/passwd`. До исправления так читались любые файлы во всех четырёх бэкендах. | ✅ | Путь сравнивается в том виде, в каком его откроет система: ссылки разрешаются по одной части пути (`os.path.realpath` в Python, `os_readlink` в native-рантайме) | `SandboxThreats.test_symlink_out_of_the_directory` |
| T2 | **`ссылка/..`**. Ядро вычисляет `..` уже после ссылки, а лексическая проверка — до неё: `data/link/../x` выглядело как `data/x`. | ✅ | Тот же разбор пути: `..` применяется к цели ссылки | `test_dotdot_after_a_symlink` |
| T3 | **`..`, абсолютные пути, похожие имена** (`data2` при праве `fs:data`). | ✅ | Сравнение по частям пути, а не по префиксу строки | `test_dotdot_and_similar_names` |
| T4 | **Ссылки и junction на Windows** не разрешаются (нет `readlink`). Создать их без прав администратора или режима разработчика нельзя, но готовая ссылка в каталоге сработает. | ⚠️ | Не давать `fs:DIR` на каталоги со ссылками; дальше — `GetFinalPathNameByHandle` в рантайме | — |
| T5 | **MCP-инструменты `klar_dev` и `klar_eval` запускали код модели со всеми правами.** `main` мог запускать программы и писать файлы, `eval` — писать файлы. Тесты были защищены и раньше: E0401 и подделки `fs`/`time`/`rand`. | ✅ | `klar mcp --allow ПРАВА` (так же `klarc mcp`): `klar_dev` и `klar_eval` получают только эти права, по умолчанию — ничего, кроме `io`. Для командной строки есть `klar dev --allow` и `klar eval --allow` | `test_mcp_runs_the_models_code_with_no_rights` |
| T6 | **`proc:NAME` даёт всё, что умеет NAME.** Например, `git -c core.pager=…` или `python -c …`. Дочерний процесс не наследует песочницу. | 📌 | Разрешать только программы без выполнения произвольного кода; `proc` — это доверие программе | `test_proc_name_is_exact` |
| T7 | **Подмена программы через PATH.** `proc:git` ищет `git` в PATH; при праве `fs` на каталог из PATH можно подложить свой `git`. | ⚠️ | Не давать `fs` на каталоги из PATH; дальше — полный путь в праве (`proc:/usr/bin/git`) | — |
| T8 | **Секреты окружения.** `env_var` относится к `io`, который разрешён всегда: программа читала `ANTHROPIC_API_KEY` и печатала его в вывод, который попадает в лог агента. | ✅ | Право `env` (все переменные) или `env:ИМЯ` (одна): без него при `--allow` `env_var` возвращает `None` во всех четырёх бэкендах. Без `--allow` проверки нет (T12) | `test_env_needs_the_env_right` |
| T9 | **Ресурсы**: бесконечный цикл, память, гигабайты вывода. Права время и память не ограничивают. | ⚠️ | Время: `--timeout N` для `run`, `build`, `test` и `dev` в klar и klarc (у `test`, `dev`, `eval` и REPL 10 с по умолчанию) останавливает программу ошибкой R0018 там, где она крутится, во всех бэкендах. Память и вывод — внешние лимиты (`ulimit`, контейнер); `klar dev --max-output` ограничивает только отчёт | `TimeLimit` |
| T10 | **Внедрение кода в Python-бэкенд** через строки (`"""`, `'''`, `\0`, фигурные скобки). | ✅ | Строки попадают в сгенерированный код через `repr`, имена — только идентификаторы грамматики | `test_strings_cannot_break_out_of_generated_python` |
| T11 | **Подмена ссылки между проверкой и открытием** (TOCTOU). | 📌 | Создать ссылку программа может только через `proc`, а это уже полное доверие (T6) | — |
| T12 | **Без `--allow` проверок нет**: программа может всё, что объявляют её `uses`. | 📌 | Для недоверенного кода — всегда `--allow` | — |
