# Klar 0.5 — спецификация языка

Краткая версия для промптов — `klar spec` (файл `klar/ai_reference.md` + автогенерация stdlib).
Здесь — полное описание с грамматикой и семантикой.

## 1. Лексика

| Элемент | Правило |
|---|---|
| Кодировка | UTF-8 |
| Комментарии | `// до конца строки`; `/// doc-комментарий` перед объявлением верхнего уровня |
| Идентификаторы | `[A-Za-z_][A-Za-z0-9_]*` |
| Ключевые слова | `module use fn type enum const let var return if else while for in break continue match test property assert requires ensures uses and or not true false with` |
| Целые | `42`, `1_000_000` (произвольная точность) |
| Дробные | `3.14`, `0.5` (цифра обязательна с обеих сторон точки) |
| Строки | `"..."`, экранирование `\n \t \\ \" \{ \} \0 \r`, интерполяция `{expr}` |
| Операторы | `+ - * / % == != < > <= >= = -> => ( ) [ ] { } , : . ?` |
| Конец инструкции | перевод строки (внутри `()` и `[]` игнорируется; строка, начинающаяся с `.`, продолжает предыдущую; строка, заканчивающаяся бинарным оператором, продолжается на следующей) |

Лексер отклоняет «чужие» токены с подсказкой: `&& || ! ; ++ -- += -= *= :: ' | & # @` (E0001).

## 2. Грамматика (EBNF)

```ebnf
program     = [ "module" ident { "." ident } NL ] { use_decl NL } { [ doc ] [ "pub" ] decl NL } ;
                                                     (* pub: fn, type, enum, const, trait *)
use_decl    = "use" ident { "." ident } "." "{" ident { "," ident } "}" ;   (* только явные имена *)
doc         = { "///" text NL } ;                    (* строки "/// >>> stmt" — doc-тесты *)
decl        = fn_decl | type_decl | alias_decl | newtype_decl | enum_decl | trait_decl | impl_decl | const_decl | test_decl
            | property_decl ;

fn_decl     = "fn" ident [ tparams ]
              "(" [ param { "," param } ] ")" [ "->" type ]
              [ "uses" ident { "," ident } ]
              { NL? ( "requires" expr | "ensures" expr ) }
              block ;
tparams     = "[" tparam { "," tparam } "]" ;
tparam      = Ident [ ":" Ident { "+" Ident } ] ;              (* ограничения — только у функций *)
param       = ident ":" type ;
trait_decl  = "trait" Ident "{" { [ doc ] method_sig [ block ] NL } "}" ;   (* тело = метод по умолчанию *)
impl_decl   = "impl" [ type_params ] Ident "for" type "{" { [ doc ] method_sig block NL } "}" ;
method_sig  = "fn" ident "(" "self" { "," param } ")" [ "->" type ] [ "uses" ident { "," ident } ]
              { NL? ( "requires" expr | "ensures" expr ) } ;    (* в сигнатурах доступен тип Self *)
type_decl   = "type" Ident [ tparams ] "{" { ident ":" type [","] } "}" ;
alias_decl  = "type" Ident [ tparams ] "=" type ;
newtype_decl = "type" Ident [ tparams ] "=" "new" type { NL "requires" expr } ;   (* `new` here is not a keyword *)
enum_decl   = "enum" Ident [ tparams ] "{" { Ident [ "(" ident ":" type { "," ident ":" type } ")" ] [","] } "}" ;
const_decl  = "const" UPPER_IDENT ":" type "=" expr ;                    (* чистое выражение *)
test_decl   = "test" string block ;
property_decl = "property" string "(" param { "," param } ")" block ;

type        = Ident [ "[" type { "," type } "]" ]
            | "fn" "(" [ type { "," type } ] ")" "->" type ;

block       = "{" { stmt NL } "}" ;
stmt        = ("let" | "var") ident [ ":" type ] "=" expr
            | ident "=" expr
            | "return" [ expr ]
            | if_stmt
            | "while" expr block
            | "for" ident "in" expr block
            | "break" | "continue"
            | "assert" expr [ "," expr ]
            | expr ;
if_stmt     = "if" expr block [ "else" ( if_stmt | block ) ] ;

expr        = or ;
or          = and { "or" and } ;
and         = not { "and" not } ;
not         = "not" not | cmp ;
cmp         = add [ ("=="|"!="|"<"|">"|"<="|">=") add ] ;      (* без цепочек *)
add         = mul { ("+"|"-") mul } ;
mul         = unary { ("*"|"/"|"%") unary } ;
unary       = "-" unary | postfix ;
postfix     = primary { "(" args ")" | "." ident [ "(" args ")" ] | "?" | "with" field_inits } ;
args        = [ arg { "," arg } [","] ] ;
arg         = [ ident ":" ] expr ;
primary     = int | float | string | "true" | "false" | "(" ")" | "(" expr ")"
            | "[" [ expr { "," expr } [","] ] "]"
            | "Map" "{" { expr ":" expr [","] } "}"
            | Ident field_inits                     (* литерал записи *)
            | ident
            | match
            | "fn" "(" [ ident [":" type] { "," ident [":" type] } ] ")" [ "->" type ] ( "=>" expr | block ) ;
field_inits = "{" { ident ":" expr [","] } "}" ;
match       = "match" expr "{" { pattern [ "if" expr ] "=>" ( expr | block ) [","] } "}" ;
pattern     = "_" | ident | int | float | string | "true" | "false" | "-" int
            | ("Some" | "Ok" | "Err") "(" pattern ")" | "None"
            | Ident "." Ident [ "(" pattern { "," pattern } ")" ] ;
```

В условиях `if`/`while`/`for`/`match`/контрактов литерал записи `Name { ... }` запрещён (как в Rust), чтобы `{` однозначно начинал блок.

## 3. Типы

| Тип | Значения | Примечания |
|---|---|---|
| `Int` | целые произвольной точности | `/` усекает к нулю, `%` — знак делимого; деление на 0 → R0001 |
| `Float` | IEEE-754 double | деление на 0.0 → R0001; биты: `x.to_bits()` (Int), `float_from_bits(n)` |
| `Bool` | `true`, `false` | |
| `Str` | строки Unicode | неизменяемые |
| `Bytes` | `bytes_of([1, 255])`, `s.to_bytes()` | неизменяемые байты 0..255; `push`/`set` в цикле `b = b.push(x)` пишут на месте; `read_bytes`/`write_bytes` |
| `Unit` | `()` | результат функций без `->` |
| `Never` | — | тип `fail(...)`; совместим с любым типом |
| `List[T]` | `[a, b]` | неизменяемый |
| `Map[K, V]` | `Map { k: v }` | ключи `Int`/`Str`/`Bool`, порядок вставки |
| `Option[T]` | `Some(v)`, `None` | |
| `Result[T, E]` | `Ok(v)`, `Err(e)` | |
| `fn(A) -> R` | лямбды, функции | |
| `type X {..}` | `X { f: v }` | номинальная запись; может быть обобщённой: `type Box[T] { value: T }` |
| `enum E {..}` | `E.V`, `E.V(f: v)` | номинальная сумма; может быть обобщённой и рекурсивной |
| `type A = B` | — | прозрачный алиас |
| `type M = new B` | `M(v)` | newtype: отдельный номинальный тип над `B`, значение — `m.value` |

**Newtype.** `type Meters = new Float` объявляет новый тип: `Meters` и `Float` не взаимозаменяемы (E0202 с подсказкой
«оберните: `Meters(value)`» или «прочитайте `.value`»). Это запись с одним полем `value`, но построить её можно только
конструктором `Meters(x)` (или `Meters(value: x)`): литерал `Meters { value: x }` и `m with { ... }` — ошибка E0217.
Строки `requires` после объявления — инвариант типа, это предусловие конструктора: каждое значение `Percent` из
`type Percent = new Int` + `requires value >= 0` + `requires value <= 100` проверено (R0002 при запуске, E0703 при
компиляции, если аргумент известен). Newtype может быть обобщённым (`type Id[T] = new Int`: `Id[User]` и `Id[Order]` не
смешиваются), иметь `impl` и `pub`; `use m.{Meters}` импортирует и тип, и конструктор. Печатается как запись:
`Meters { value: 3.5 }`. Ключом `Map` newtype быть не может (как и любая запись).

Прелюдия (доступна всегда): `Pair[A, B] { first, second }`, `Entry[K, V] { key, value }`, `Indexed[T] { index, value }`, константы `PI`, `E`.

**Вывод типов.** Обязательно аннотируются параметры и (если не `Unit`) результат функций. Остальное выводится унификацией. Обобщённые параметры (`[T]`) внутри тела функции — «жёсткие»: с ними можно только сравнивать на равенство, передавать дальше, вызывать `.to_str()` и методы трейтов из ограничения (`[T: Shape]`).

**Трейты.** `trait T { ... }` перечисляет методы (первый параметр всегда `self`, его тип — `Self`). Метод с телом —
метод по умолчанию. `impl T for X` пишется для `Int`, `Float`, `Bool`, `Str`, `Bytes` и своих `type`/`enum`. Он обязан
определить все методы без тела с теми же именами и типами параметров (`Self` = `X`), тем же результатом и не
более широкими эффектами (E0221). Для обобщённого типа `impl` тоже обобщённый и покрывает все его экземпляры:
`impl[T: Show] Show for List[T]`, `impl[K, V] Show for Map[K, V]`, `impl[T] Show for Box[T]` — аргументы цели
ровно параметры `impl`, каждый по одному разу (E0221; специализаций вроде `impl Show for List[Int]` нет).
Ограничения параметров `impl` действуют внутри его методов, а при использовании: `List[X]` реализует `Show`, только
если `X` реализует `Show` (E0220 с подсказкой, какого `impl` не хватает). Для каждой пары (трейт, тип) в программе не больше одного `impl`, и он находится
в модуле трейта или в модуле типа (E0222). Ограничение `fn f[A: T + U](...)` разрешает вызывать методы `T` и `U`
у значений типа `A`; при вызове `f` тип-аргумент обязан реализовывать трейты (E0220) и должен выводиться (E0223).
Трейт не является типом (E0224): разнородные значения — через `enum` с `impl` для него. Методы трейта видны у
значения, если трейт импортирован в модуль (как в Rust). Нативный компилятор специализирует обобщённую функцию
для каждого набора типов и вызывает реализацию напрямую. Интерпретатор выбирает реализацию по типу значения.
Результат одинаков.

**Эквивалентность.** `==` структурное для всех значений, кроме функций (их сравнивать нельзя).

## 4. Семантика

* **Неизменяемость.** Все значения неизменяемы. `let` — привязка без переназначения, `var` — с переназначением. Поля записей не присваиваются; обновление — `rec with { f: v }`.
* **Области видимости.** Блочные. Затенение любого видимого имени (включая имена функций) запрещено — E0102.
* **Возврат.** Явный `return` на каждом пути (E0205). Пути, заканчивающиеся `fail(...)`, `while true` без `break` или `match`, все ветви которого возвращают, считаются завершёнными.
* **Вызовы.** Позиционные, затем именованные аргументы. Для пользовательских функций с ≥3 параметрами — только именованные (E0208).
* **Синтаксис методов (UFCS).** `x.f(a)` ищется: (1) поле-функция записи, (2) встроенный метод типа, (3) метод трейта (у `impl` типа `x` или из ограничения параметра типа), (4) пользовательская функция `f`, первый параметр которой подходит к типу `x`. Методы трейтов вызываются только через точку.
* **`?`.** `Some(v)?`/`Ok(v)?` → `v`; `None?`/`Err(e)?` → немедленный `return` того же значения. Тип ошибки должен совпадать с типом ошибки функции (E0212). В тесте — провал теста (R0008). В `main` с `-> Result` — `Err` завершает программу (R0007).
* **Контракты.** `requires` проверяются при входе, `ensures` — при выходе (имя `result`). Чистые, без `?`. Нарушение → R0002/R0003 с текстом условия и значениями переменных.
* **Эффекты** (`io`, `time`, `rand`, `fs`, `net`, `proc` — запуск других программ). Множество эффектов функции должно включать эффекты всех вызываемых функций (E0401). Лямбда наследует эффекты окружающей функции. Тесты: только `io`.
* **Игнорирование значений.** Выброшенный `Result` → E0402; выброшенный результат «обновляющего» метода (`push`, `set`, `with`, …) → E0405; прочие не-`Unit` → W0401.
* **Сопоставление.** `match` исчерпывающий (E0301) для `Bool`, `Option`, `Result`, пользовательских `enum`; для остальных типов нужен `_`. Вариант считается покрытым, если все его вложенные шаблоны неопровержимы (`_` или имя).
* **Порядок вычислений.** Слева направо; `and`/`or` — ленивые.
* **Детерминизм.** Без эффектов `time`/`rand` программа детерминирована.
* **Модули.** `use a.b.{x, Y}` загружает `a/b.klar` рядом с файлом (или стандартный модуль `std.*`). Импорт только явный, циклы запрещены (E0602), имена типов уникальны во всей программе. Импортировать можно только объявления с `pub` (E0606); прелюдия видна всем модулям. Закрытая функция, которую в модуле никто не вызывает, — W0406. `impl` видим везде, где виден его трейт.
* **Константы.** `const NAME: T = expr` — вычисляется один раз до `main`, выражение чистое.
* **Guard'ы.** `pattern if cond => ...`; ветка с guard'ом не учитывается при проверке полноты.

## 5. Тесты

```klar
test "описание" {
  let x = compute(2)?          // Err/None → тест провален (R0008)
  assert x == 4                // при провале: left = ..., right = ...
  assert x > 0, "должно быть положительным"
}
```
```klar
/// Удваивает число.
/// >>> assert double(21) == 42
fn double(x: Int) -> Int { return x * 2 }

property "reverse twice is identity" (xs: List[Int]) {
  assert xs.reverse().reverse() == xs
}
```
Doc-тесты (`/// >>>`) — это тесты. `property` запускается на 100 случайных входах (`--runs`, `--seed`); при провале
печатается минимальный контрпример после сжатия. `klar test file.klar [-k фильтр] [--json]`. Вывод `print`
внутри теста показывается только при провале.

## 6. Коды диагностик

`E00xx` — лексика/синтаксис, `E01xx` — объявления, `E02xx` — выражения и типы, `E03xx` — `match`, `E04xx` — эффекты и значения, `E05xx` — программа, `Wxxxx` — предупреждения, `Rxxxx` — ошибки времени выполнения. Полный список: `klar explain <код>` или `klar/diagnostics.py`.

## 7. Стандартная библиотека

Генерируется командой `klar spec` из сигнатур в `klar/builtins.py`. Глобальные функции: `print`, `read_line`, `cli_args`, `dbg`, `fail`, `todo`, `range`, `now_ms`, `now_ns`, `random_int`, `read_file`, `write_file`, `file_exists`, `Some`, `Ok`, `Err`. Методы есть у `Int`, `Float`, `Str`, `List`, `Map`, `Option`, `Result` (~110 всего); `.to_str()` есть у всех значений. Модули на Klar: `std.math`, `std.text`, `std.list`, `std.result`.

## 8. Модель исполнения

Семантика одинакова на всех бэкендах (проверяется дифференциальными тестами):
* **native** (по умолчанию для `klar run` и `klar build`): машинный код x86-64, Linux ELF / Windows PE, без зависимостей;
* **--py**: компиляция в байткод Python (запасной путь);
* **--interp**: эталонный интерпретатор (им же работают `klar test` и `klar profile`).

Время выполнения: `Int` переполняется в большие числа автоматически; глубина рекурсии ограничена 10 000 вызовов (R0006);
ошибки времени выполнения печатают код, место, значения и стек вызовов Klar.
