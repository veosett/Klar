# Klar 1.0 — спецификация языка

Это описание языка Klar версии 1.0: лексика, грамматика, типы, семантика, тесты, модули и пакеты, модель исполнения
([in English](SPEC.en.md)).
Краткая версия для промптов — `klar spec` (файл `klar/ai_reference.md` и сигнатуры стандартной библиотеки).
Эталон поведения — интерпретатор `klar/interpreter.py` вместе с проверкой типов `klar/checker.py`; оба компилятора
(`klar` на Python и `klarc` на Klar) обязаны давать то же, что эталон, и это проверяется тестами (раздел 10).

## 0. Стабильность

Klar следует [семантическому версионированию](https://semver.org/). Начиная с 1.0 в версиях 1.x гарантируется:

* **Исходный код.** Программа, которая проходит `klar check` в 1.0, проходит его во всех 1.x и делает то же самое.
  Новых ключевых слов в 1.x не будет. Единственное исключение — новые встроенные функции и методы, которые
  появляются в минорных версиях (1.1, 1.2, …): если программа уже называет так свою функцию, компилятор сообщит об
  этом (E0101/E0102; метод `impl` с именем нового встроенного метода — E0221), а в синтаксисе методов встроенный
  метод важнее пользовательской функции (раздел 4). Поэтому каждое новое встроенное имя указывается в CHANGELOG.
* **Коды диагностик.** Код (`E0205`, `R0002`, `W0401`, …) сохраняет свой смысл; новые проверки получают новые
  коды. Текст сообщений, подсказки и предлагаемые исправления могут меняться.
* **Предупреждения** могут добавляться (программа с новым предупреждением по-прежнему компилируется).
* **Стандартная библиотека.** Сигнатуры встроенных функций, методов и модулей `std.*` не меняются и не удаляются,
  новые только добавляются.
* **Формат `klar.toml` и `klar.lock`** — только совместимые расширения.
* **Машиночитаемый вывод** инструментов (`--json`) — поля не удаляются и не меняют смысл, новые могут появляться.

Не гарантируются: скорость, размер и внутреннее устройство исполняемых файлов, текст `klar spec`, внутренние
интерфейсы компиляторов (`klar/*.py`, `compiler/*.klar`, `klar/rt/*.klar`) и всё, что помечено как
**экспериментальное** (сейчас: цель `macos`, раздел 9). Ошибки, при которых реализация расходится с этой
спецификацией, исправляются в пользу спецификации.

## 1. Лексика

| Элемент | Правило |
|---|---|
| Кодировка | UTF-8 |
| Комментарии | `// до конца строки`; `/// doc-комментарий` перед объявлением верхнего уровня |
| Идентификаторы | буква или `_`, затем буквы, цифры, `_` (буквы не только латинские, но имена не из ASCII получают предупреждение W0104); типы, трейты и варианты — `PascalCase`, функции и переменные — `snake_case`, константы — `UPPER_SNAKE_CASE`; `_x` — намеренно неиспользуемое имя |
| Ключевые слова | `module use pub fn type enum trait impl const let var return if else while for in break continue match test property assert requires ensures uses and or not true false with` |
| Целые | `42`, `1_000_000`, `0xFF`, `0b1010`, `0o17` (произвольная точность; цифры ASCII, суффиксов нет) |
| Дробные | `3.14`, `0.5`, `1e-5`, `2.5E10` (цифра обязательна с обеих сторон точки; с порядком — всегда `Float`) |
| Строки | `"..."`, экранирование `\n \t \r \0 \\ \" \{ \}`, интерполяция `{expr}` (внутри `{...}` строковых литералов нет); `{` перед `"`, `\` или `}` — просто скобка: `"{"`, `"{}"` |
| Операторы | `+ - * / % == != < > <= >= = -> => ( ) [ ] { } , : . ?` |
| Конец инструкции | перевод строки (внутри `()` и `[]` игнорируется; строка, начинающаяся с `.`, продолжает предыдущую; строка, заканчивающаяся бинарным оператором, продолжается на следующей) |

Лексер отклоняет «чужие» токены с подсказкой: `&& || ! ; ++ -- += -= *= :: ' | & ^ ~ << >> # @` и обратную
кавычку (E0001).

## 2. Грамматика (EBNF)

```ebnf
program     = [ "module" ident { "." ident } NL ] { use_decl NL } { [ doc ] [ "pub" ] decl NL } ;
                                                     (* pub: fn, type, enum, const, trait *)
use_decl    = "use" ident { "." ident } "." "{" ident { "," ident } "}" ;   (* только явные имена *)
doc         = { "///" text NL } ;                    (* строки "/// >>> stmt" — doc-тесты *)
decl        = fn_decl | type_decl | alias_decl | newtype_decl | enum_decl | trait_decl | impl_decl | const_decl | test_decl
            | property_decl ;

fn_decl     = "fn" ident [ tparams ]
              "(" [ param { "," param } ] ")" [ "->" type ]
              [ "uses" ident { "," ident } ]
              { NL? ( "requires" expr | "ensures" expr ) }
              block ;
tparams     = "[" tparam { "," tparam } "]" ;
tparam      = Ident [ ":" Ident { "+" Ident } ] ;              (* ограничения — только у функций и impl *)
param       = ident ":" type ;
trait_decl  = "trait" Ident "{" { [ doc ] method_sig [ block ] NL } "}" ;   (* тело = метод по умолчанию *)
impl_decl   = "impl" [ tparams ] Ident "for" type "{" { [ doc ] method_sig block NL } "}" ;
method_sig  = "fn" ident "(" "self" { "," param } ")" [ "->" type ] [ "uses" ident { "," ident } ]
              { NL? ( "requires" expr | "ensures" expr ) } ;    (* в сигнатурах доступен тип Self *)
type_decl   = "type" Ident [ tparams ] "{" { ident ":" type [","] } "}" ;
alias_decl  = "type" Ident [ tparams ] "=" type ;
newtype_decl = "type" Ident [ tparams ] "=" "new" type { NL "requires" expr } ;   (* `new` здесь не ключевое слово *)
enum_decl   = "enum" Ident [ tparams ] "{" { Ident [ "(" ident ":" type { "," ident ":" type } ")" ] [","] } "}" ;
const_decl  = "const" UPPER_IDENT ":" type "=" expr ;                    (* чистое выражение *)
test_decl   = "test" string block ;
property_decl = "property" string "(" param { "," param } ")" block ;

type        = Ident [ "[" type { "," type } "]" ]
            | "fn" "(" [ type { "," type } ] ")" "->" type ;

block       = "{" { stmt NL } "}" ;
stmt        = ("let" | "var") ident [ ":" type ] "=" expr
            | ident "=" expr
            | "return" [ expr ]
            | if_stmt
            | "while" expr block
            | "for" ident "in" expr block
            | "break" | "continue"
            | "assert" expr [ "," expr ]
            | expr ;
if_stmt     = "if" expr block [ "else" ( if_stmt | block ) ] ;

expr        = or ;
or          = and { "or" and } ;
and         = not { "and" not } ;
not         = "not" not | cmp ;
cmp         = add [ ("=="|"!="|"<"|">"|"<="|">=") add ] ;      (* без цепочек *)
add         = mul { ("+"|"-") mul } ;
mul         = unary { ("*"|"/"|"%") unary } ;
unary       = "-" unary | postfix ;
postfix     = primary { "(" args ")" | "." ident [ "(" args ")" ] | "?" | "with" field_inits } ;
args        = [ arg { "," arg } [","] ] ;
arg         = [ ident ":" ] expr ;
primary     = int | float | string | "true" | "false" | "(" ")" | "(" expr ")"
            | "[" [ expr { "," expr } [","] ] "]"
            | "Map" "{" { expr ":" expr [","] } "}"
            | Ident field_inits                     (* литерал записи *)
            | ident
            | match
            | "fn" "(" [ ident [":" type] { "," ident [":" type] } ] ")" [ "->" type ] ( "=>" expr | block ) ;
field_inits = "{" { ident ":" expr [","] } "}" ;
match       = "match" expr "{" { pattern [ "if" expr ] "=>" ( expr | block ) [","] } "}" ;
pattern     = "_" | ident | int | float | string | "true" | "false" | "-" ( int | float )
            | ("Some" | "Ok" | "Err") "(" pattern ")" | "None"
            | Ident "." Ident [ "(" pattern { "," pattern } ")" ] ;
```

* В условиях `if`/`while`/`for`/`match`/контрактов литерал записи `Name { ... }` запрещён (как в Rust), чтобы `{`
  однозначно начинал блок.
* `if` — инструкция, а не выражение; выбор значения — `match cond { true => a, false => b }`.
* Вложенных именованных функций и переменных верхнего уровня нет (лямбды и `const`).
* Отрицательный литерал как получатель метода пишется в скобках: `(-5).abs()`.
* Ветка `match` с блоком имеет тип `Unit`, если блок не возвращается из функции.
* Все `use` стоят в начале файла, до остальных объявлений.

## 3. Типы

| Тип | Значения | Примечания |
|---|---|---|
| `Int` | целые произвольной точности | `/` усекает к нулю, `%` — знак делимого; переполнения нет |
| `Float` | IEEE-754 double | `%` — остаток с знаком делимого (`-7.5 % 2.0 == -1.5`); биты: `x.to_bits()` (Int), `float_from_bits(n)` |
| `Bool` | `true`, `false` | |
| `Str` | строки Unicode | неизменяемые; индексы и длины — в символах (кодовых точках) |
| `Bytes` | `bytes_of([1, 255])`, `s.to_bytes()` | неизменяемые байты 0..255; `push`/`set` в цикле `b = b.push(x)` пишут на месте; `read_bytes`/`write_bytes` |
| `Unit` | `()` | результат функций без `->` |
| `Never` | — | тип `fail(...)`, `todo(...)`, `exit(...)`; совместим с любым типом |
| `List[T]` | `[a, b]` | неизменяемый |
| `Map[K, V]` | `Map { k: v }`, или `{ k: v }` там, где ожидается выражение | ключ — любое значение без функций (сравнивается `==`); перебор в порядке вставки; `==` словарей от порядка не зависит |
| `Option[T]` | `Some(v)`, `None` | |
| `Result[T, E]` | `Ok(v)`, `Err(e)` | |
| `fn(A) -> R`, `fn(A) -> R uses io` | лямбды, функции (с эффектами вызова) | сравнивать функции нельзя |
| `type X {..}` | `X { f: v }` | номинальная запись; может быть обобщённой: `type Box[T] { value: T }` |
| `enum E {..}` | `E.V`, `E.V(f: v)` | номинальная сумма; может быть обобщённой и рекурсивной |
| `type A = B` | — | прозрачный алиас |
| `type M = new B` | `M(v)` | newtype: отдельный номинальный тип над `B`, значение — `m.value` |

**Newtype.** `type Meters = new Float` объявляет новый тип: `Meters` и `Float` не взаимозаменяемы (E0202 с подсказкой
«оберните: `Meters(value)`» или «прочитайте `.value`»). Это запись с одним полем `value`, но построить её можно только
конструктором `Meters(x)` (или `Meters(value: x)`): литерал `Meters { value: x }` и `m with { ... }` — ошибка E0217.
Строки `requires` после объявления — инвариант типа, это предусловие конструктора: каждое значение `Percent` из
`type Percent = new Int` + `requires value >= 0` + `requires value <= 100` проверено (R0002 при запуске, E0703 при
компиляции, если аргумент известен). Newtype может быть обобщённым (`type Id[T] = new Int`: `Id[User]` и `Id[Order]` не
смешиваются), иметь `impl` и `pub`; `use m.{Meters}` импортирует и тип, и конструктор. Печатается как запись:
`Meters { value: 3.5 }`. Входом `property` newtype с `requires` быть не может (E0605: случайные значения нарушали бы
инвариант) — генерируйте исходное значение и стройте newtype внутри.

Прелюдия (доступна всегда): `Pair[A, B] { first, second }`, `Entry[K, V] { key, value }`, `Indexed[T] { index, value }`,
константы `PI`, `E`.

**Вывод типов.** Обязательно аннотируются параметры и (если не `Unit`) результат функций. Остальное выводится
унификацией; пустые коллекции аннотируются (`let xs: List[Int] = []`). Обобщённые параметры (`[T]`) внутри тела
функции — «жёсткие»: с ними можно только сравнивать на равенство, передавать дальше, вызывать `.to_str()` и методы
трейтов из ограничения (`[T: Shape]`).

**Трейты.** `trait T { ... }` перечисляет методы (первый параметр всегда `self`, его тип — `Self`). Метод с телом —
метод по умолчанию. `impl T for X` пишется для `Int`, `Float`, `Bool`, `Str`, `Bytes` и своих `type`/`enum`. Он обязан
определить все методы без тела с теми же именами и типами параметров (`Self` = `X`), тем же результатом и не
более широкими эффектами (E0221). Для обобщённого типа `impl` тоже обобщённый и покрывает все его экземпляры:
`impl[T: Show] Show for List[T]`, `impl[K, V] Show for Map[K, V]`, `impl[T] Show for Box[T]` — аргументы цели
ровно параметры `impl`, каждый по одному разу (E0221; специализаций вроде `impl Show for List[Int]` нет).
Ограничения параметров `impl` действуют внутри его методов, а при использовании: `List[X]` реализует `Show`, только
если `X` реализует `Show` (E0220 с подсказкой, какого `impl` не хватает). Для каждой пары (трейт, тип) в программе не
больше одного `impl`, и он находится в модуле трейта или в модуле типа (E0222). Ограничение `fn f[A: T + U](...)`
разрешает вызывать методы `T` и `U` у значений типа `A`; при вызове `f` тип-аргумент обязан реализовывать трейты
(E0220) и должен выводиться (E0223). Трейт не является типом (E0224): разнородные значения — через `enum` с `impl` для
него. Методы трейта видны у значения, если трейт импортирован в модуль (как в Rust), и вызываются только через точку.
Нативный компилятор специализирует обобщённую функцию для каждого набора типов и вызывает реализацию напрямую,
интерпретатор выбирает реализацию по типу значения; результат одинаков.

**Эквивалентность.** `==` структурное. Значения, в которых есть функции (и сами функции, и записи, списки, `Option`
с функциями внутри), сравнивать нельзя (E0211). `<`, `>`, `<=`, `>=` определены для `Int`, `Float`, `Str` (E0211 для
остальных); `sort`, `min`, `max` — для списков из них (E0215; записи — через `sort_by`).

## 4. Семантика

* **Неизменяемость.** Все значения неизменяемы. `let` — привязка без переназначения, `var` — с переназначением.
  Поля записей не присваиваются; обновление — `rec with { f: v }`. Методы коллекций возвращают новые значения
  (`xs = xs.push(1)`).
* **Области видимости.** Блочные. Затенение любого видимого имени (включая имена функций) запрещено — E0102.
  Имена типов уникальны во всей программе.
* **Возврат.** Явный `return` на каждом пути (E0205). Пути, заканчивающиеся `fail(...)`, `todo(...)`, `exit(...)`,
  `while true` без `break` в теле (даже во вложенном цикле) или `match`, все ветви которого завершаются, считаются
  завершёнными.
* **Вызовы.** Позиционные, затем именованные аргументы. У пользовательских функций с ≥3 параметрами позиционные
  аргументы разрешены, только когда их нельзя незаметно перепутать (E0208). Параметры разных типов не перепутать:
  не сойдутся типы. Среди параметров одного типа все аргументы, кроме самое большее одного, должны носить имя своего
  параметра: `r` или `nr` для `r`, `r - 1`, `p.r`. Иначе — `f(200, 20, 10)`, `cell(g, i, j)` — аргументы
  называются по имени. Аргумент с именем другого параметра (`cell(g, c, r)`) — ошибка «аргументы перепутаны».
* **Синтаксис методов (UFCS).** `x.f(a)` ищется: (1) поле-функция записи, (2) встроенный метод типа, (3) метод трейта
  (у `impl` типа `x` или из ограничения параметра типа), (4) пользовательская функция `f`, первый параметр которой
  подходит к типу `x`.
* **Лямбды** захватывают значения `let` (копией), но не `var` (E0216). Лямбда наследует эффекты окружающей функции.
  `?` и `return` внутри лямбды завершают лямбду, а не окружающую функцию.
* **Циклы.** `for x in xs` — только по `List` (E0202: для словаря — `m.keys()`, для строки — `s.chars()`);
  `range(a, b)` — список `a..b-1`. `break`/`continue` — только внутри цикла (E0213).
* **`?`.** `Some(v)?`/`Ok(v)?` → `v`; `None?`/`Err(e)?` → немедленный `return` того же значения. Тип ошибки должен
  совпадать с типом ошибки функции (E0212). В тесте — провал теста (R0008). В `main` с `-> Result` — `Err` завершает
  программу (R0007).
* **Контракты.** `requires` проверяются при входе, `ensures` — при выходе (имя `result`). Чистые, без `?`. Нарушение →
  R0002/R0003 с текстом условия и значениями переменных. Простые контракты (сравнения параметра или `result` и его
  `len()` с числовым литералом, `is_empty()`, `not`, `and`) проверяются и при компиляции по знаковому анализу: вызов, где
  известные знаки аргумента противоречат `requires`, — E0703 (`if n <= 0 { sqrt_int(n) }` при `requires n >= 0`);
  `return`, чьё значение противоречит `ensures`, — E0706. Доказать контракт компилятор не обязан: ошибка — только когда
  нарушение неизбежно.
* **Безопасность до запуска.** Целочисленные `a / b` и `a % b` компилируются, только если `b` доказуемо не ноль
  (E0701: ненулевой литерал или константа, проверка `b != 0` выше по пути, `requires`, `assert`, `ensures` функции,
  которая дала `b`, и т. п.). Функция, которая на каждом пути вызывает себя, — E0702. Вызовы с константными
  аргументами проверяются по `requires` (E0703) и по областям определения встроенных функций (E0704).
* **Эффекты** (`io`, `time`, `rand`, `fs`, `net`, `proc` — запуск других программ). Множество эффектов функции должно
  включать эффекты всех функций, которые она вызывает, — по имени и через функции-значения (E0401); неизвестный
  эффект — E0403. Функция без `uses` чистая без исключений.
* **Эффекты в типах функций.** Тип `fn(A) -> R uses io, fs` — функция, вызов которой может делать эти эффекты;
  `fn(A) -> R` без `uses` — чистая. Вызов функции-значения требует эффектов её типа. Функция по имени как значение
  получает тип со своими `uses`; лямбда — с эффектами, которые использует её тело. Функция с меньшим набором эффектов
  подходит туда, где разрешён больший (`show_item` с `uses io` и чистая лямбда подходят к `fn(Int) -> Unit uses io`),
  обратное — E0202. Тело лямбды, переданной туда, где написан тип функции, может использовать ровно эффекты этого
  типа (иначе E0401); в остальных случаях — эффекты окружающей функции. Встроенные функции высшего порядка (`map`,
  `filter`, `fold`, `each`-подобные, `Option.map`, `Map.update`, …) полиморфны по эффектам: вызов требует эффектов
  переданной функции. Функция неизвестного типа (параметр лямбды без типа) вызывается как чистая. Эффекты функций в
  типе `var` фиксируются при объявлении. В типе возврата объявления `uses` относится к объявлению; функцию, которая
  возвращает функцию с эффектами, пишут со скобками: `fn make() -> (fn(Str) -> Unit uses io)`. В списке параметров
  запятая после эффектов продолжает их, только если дальше имя эффекта без `:`. Контракты и константы чистые. Тесты
  и свойства используют `io` и объявленные подделки `fs`, `time`, `rand` (раздел 5); `proc` и `net` в тестах — E0401.
* **Параллелизм.** `xs.par_map(f)` — значение то же, что у `xs.map(f)` (элементы и порядок). Аргумент — лямбда, которая
  не использует эффекты (её тело проверяется с пустым множеством эффектов, вложенные лямбды тоже, вызовы
  функций-значений с эффектами — тоже E0401), или любое выражение функционального типа без `uses` (иначе E0406). Тип результата `U` не должен содержать функций,
  в том числе внутри записей, вариантов, списков и словарей (E0406). Ошибка выполнения внутри `f` сообщается так же, как у `map`: для первого по порядку элемента, на котором `f`
  падает. Других способов разделять данные между потоками исполнения в языке нет, поэтому гонки данных невозможны.
* **Игнорирование значений.** Выброшенный `Result` → E0402; выброшенный результат «обновляющего» вызова (по имени
  метода: `push`, `set`, `concat`, `filter`, `map`, `sort`, `with`, …) → E0405; прочие не-`Unit` → W0401 (кроме
  `dbg(...)`). Явный отказ — `let _ = expr`.
* **Сопоставление.** `match` исчерпывающий (E0301): полнота проверяется по вложенным шаблонам (`Some(true)`,
  `Some(false)`, `None` покрывают `Option[Bool]`). Для `Int`, `Float`, `Str` нужна ветка `_` или имя. Ветка, которую
  закрывают предыдущие, — предупреждение W0303. Ветка с guard'ом (`pattern if cond => ...`) не учитывается при
  проверке полноты.
* **Порядок вычислений.** Слева направо; `and`/`or` — ленивые.
* **Детерминизм.** Без эффектов `time`/`rand` (и без чтения внешнего мира через `io`/`fs`/`net`/`proc`) программа
  детерминирована.
* **Константы.** `const NAME: T = expr` — вычисляется один раз до `main`, выражение чистое.
* **Точка входа.** `fn main()` или `fn main() -> Result[Unit, E]` (с нужными `uses`). `exit(code)` завершает программу с
  кодом `code`, приведённым к 0..255 (вывод сбрасывается). Глубина рекурсии ограничена 10 000 вызовов (R0006);
  печать, сравнение и хеширование значения, вложенного глубже 100 000 уровней, — тоже R0006; значение, которому
  нужно больше памяти, чем бывает у компьютера (`"x".repeat(10 ** 18)`), — R0015.
* **Трейты и методы.** Метод `impl` повторяет имена и типы параметров метода трейта; называться как встроенный метод
  типа (или `to_str`) он не может (E0221).

## 5. Тесты

```klar
test "описание" {
  let x = compute(2)?          // Err/None → тест провален (R0008)
  assert x == 4                // при провале: left = ..., right = ...
  assert x > 0, "должно быть положительным"
}
```
```klar
/// Удваивает число.
/// >>> assert double(21) == 42
fn double(x: Int) -> Int { return x * 2 }

property "reverse twice is identity" (xs: List[Int]) {
  assert xs.reverse().reverse() == xs
}
```
Doc-тесты (`/// >>>`, в том числе у методов трейтов и `impl`) — это тесты. `property` запускается на 100 случайных
входах (`--runs`, `--seed`, по умолчанию seed 0 — запуски воспроизводимы; `klar dev` берёт 50); входы порождаются по
типам параметров (числа, строки, списки, словари, `Option`, `Result`, записи, `enum` — в том числе рекурсивные; тип,
который нельзя породить, — E0605), при провале (R0010) печатается минимальный контрпример после сжатия; одинаковые
`--seed` дают одинаковые входы во всех реализациях. `klar test file.klar [-k фильтр] [--json]`. Вывод `print` внутри
теста показывается только при провале. `exit()` внутри теста — провал (R0013).

**Свойства из контрактов.** `klar test` (и `klar dev`, `klarc test`) проверяет каждую функцию главного файла
верхнего уровня, у которой есть `ensures`, нет параметров типа и эффектов, а входы можно породить. Её запускают на
случайных входах, удовлетворяющих `requires`, как свойство `contract: имя`. Нарушение `ensures` или любая ошибка
выполнения — провал с минимальным контрпримером. Свойство, которое пользователь назвал так же, заменяет созданное.

**Подделки эффектов.** Тест или свойство может объявить `uses fs, time, rand` после имени (у свойства — после
входов): `test "сохранение" uses fs { ... }`. Эффекты в тестах никогда не касаются настоящей системы:
* `fs` — пустая файловая система в памяти с корнем `/`; `current_dir()` — `/`, относительные пути считаются от `/`,
  `.` и `..` разрешаются; `make_dir` создаёт и промежуточные папки; ошибки — те же тексты, что у настоящих файлов
  (`No such file or directory`, `Is a directory`, `Not a directory`, `File exists`);
* `time` — часы стоят на 0 (`now_ms()`, `now_ns()`), `set_clock(ms)` переводит их (вне тестов — R0009);
* `rand` — `random_int` выдаёт одну и ту же последовательность в каждом тесте и во всех бэкендах.

Каждый тест и каждый запуск свойства начинаются с новых подделок. Вызов эффекта, который тест не объявил, — E0401
(с исправлением `uses ...`); `proc` и `net` подделок не имеют, в тестах они запрещены (E0401).

## 6. Модули и пакеты

* **Модули.** `use a.b.{x, Y}` загружает `a/b.klar` рядом с файлом (или стандартный модуль `std.*`). Импорт только
  явный, циклы запрещены (E0602). Импортировать можно только объявления с `pub` (E0606); прелюдия видна всем модулям.
  Закрытая функция, которую в модуле никто не вызывает, — W0406. `impl` видим везде, где виден его трейт.
* **Пакеты.** Проект — папка с `klar.toml` (ищется от главного файла вверх): `[package]` (`name`, `version`,
  `description`, `authors`, `license`) и `[dependencies]` вида `имя = { path = "..." }` или
  `имя = { git = "...", tag|rev|branch = "..." }`; формат — подмножество TOML (строки, целые, `true`/`false`,
  встроенные таблицы, массивы строк, комментарии `#`), ошибки — E0610. Если первая часть `use` — зависимость пакета,
  которому принадлежит файл, `use d.{x}` загружает `<d>/lib.klar`, `use d.a.b.{x}` — `<d>/a/b.klar`; модули
  зависимости называются `d`, `d.a.b`. Зависимость — папка с `klar.toml` (иначе E0609; git-зависимости лежат в
  `<проект>/.klar/deps/<имя>`, их кладёт `klar fetch`, а `klar.lock` закрепляет коммиты). Имя, которое одновременно
  зависимость и файл рядом, — E0607; одно имя с разными источниками в разных манифестах — E0608.

## 7. Коды диагностик

`E00xx` — лексика и синтаксис, `E01xx` — объявления и имена, `E02xx` — выражения и типы, `E03xx` — `match`, `E04xx` —
эффекты и значения, `E05xx` — программа, `E06xx` — модули и пакеты, `E07xx` — проверки безопасности и контрактов при
компиляции, `Wxxxx` — предупреждения, `Rxxxx` — ошибки времени выполнения. Полный список с объяснениями и примерами:
`klar explain <код>` (`klar/diagnostics.py`). Деление на ноль: для `Int` делитель, который может быть нулём, — E0701
при компиляции; для `Float` литерал `0.0` — E0701, вычисленный ноль — R0001 при выполнении. Ошибка времени выполнения
печатает код, место, значения переменных условия и стек вызовов Klar; машиночитаемо — `--json`.

## 8. Стандартная библиотека

Полный список с сигнатурами генерирует `klar spec` (из `klar/builtins.py`), примеры к каждому имени — `klar doc <имя>`.

* **Глобальные функции:** `print`, `print_raw`, `eprint`, `read_line`, `read_exact`, `cli_args`, `dbg`, `fail`, `todo`,
  `exit`, `range`, `bytes_of`, `float_from_bits`, `now_ms`, `now_ns`, `random_int`, `env_var`, `read_file`,
  `write_file`, `read_bytes`, `write_bytes`, `file_exists`, `is_dir`, `list_dir`, `make_dir`, `remove_file`,
  `current_dir`, `set_executable`, `run_command`, `run_capture`, `set_clock` (только в тестах), `Some`, `Ok`, `Err`.
* **Методы** есть у `Int`, `Float`, `Str`, `Bytes`, `List`, `Map`, `Option`, `Result`; `.to_str()` есть у всех значений.
* **Модули на Klar:** `std.math`, `std.text`, `std.list`, `std.result`, `std.set`, `std.json`, `std.time` (даты, ISO 8601,
  смещения часовых поясов), `std.path` (пути как текст), `std.csv` (RFC 4180), `std.regex` (регулярные выражения),
  `std.hash` (CRC-32, FNV-1a, SHA-256), `std.numfmt` (разряды, проценты, размеры, порядковые и римские числа). У каждой
  функции есть пример-тест (`klar doc имя`).

Ошибки внешнего мира — значения, а не аварии: файлы, каталоги и запуск программ возвращают `Result`, `read_line` и
`env_var` — `Option`. Аварийно завершают программу только `fail`, `todo` и `exit`.

## 9. Модель исполнения

Семантика одинакова на всех бэкендах (проверяется дифференциальными тестами):

* **native** (по умолчанию для `klar run` и `klar build`; `klarc` строит только его): машинный код без зависимостей —
  x86-64 Linux (ELF), x86-64 Windows (PE, только `kernel32.dll`), AArch64 Linux (ELF) и, **экспериментально**,
  x86-64 macOS (Mach-O: статический файл без dyld, системные вызовы BSD; цель `--target macos` выбирается только
  явно). `par_map` на Linux и macOS распределяет куски списка по рабочим процессам (fork, по одному на ядро, не
  больше 64), на Windows выполняется как `map`;
* **--py**: компиляция в байткод Python (запасной путь);
* **--interp**: эталонный интерпретатор (им же по умолчанию работают `klar test` и `klar profile`).

`Int` переходит в большие числа автоматически; память освобождается подсчётом ссылок (циклов в неизменяемых значениях
не бывает). Ошибки времени выполнения печатают код, место, значения и стек вызовов Klar.

**Права при запуске.** `klar run --allow ПРАВА` и `klar build --allow ПРАВА` (так же `klarc run/build`) превращают
эффекты в права и во время выполнения: вызов вне прав — ошибка R0016 с именем права, которого не хватило. `io`
(печать, ввод, `env_var`, `cli_args`) разрешён всегда. Права через запятую:
* `fs` — все файлы; `fs:ПАПКА` — файлы и папки внутри ПАПКИ (относительно рабочей папки при запуске; пути
  сравниваются как написаны, после разрешения `.` и `..`, `\` тоже разделитель; символические ссылки не
  раскрываются); `current_dir()` требует любого права `fs`;
* `proc` — любые программы; `proc:ИМЯ` — только `run_command([ИМЯ, ...])` и `run_capture([ИМЯ, ...], ...)`; без
  `proc` нельзя запустить ни одну программу, поэтому код без права `fs` не прочитает файлы и через `cat`;
* `time`, `rand`, `net`.

**Запись и повтор.** `klar run --record T.json файл.klar` записывает всё, что программа получила снаружи: ввод,
аргументы, переменные окружения, часы, случайные числа, прочитанные файлы и папки, результаты запущенных программ
и записей в файлы. `klar replay T.json` запускает программу снова на этих данных, без настоящих файлов, часов и
ввода, и ничего не пишет наружу. Вывод, ошибка и код выхода совпадают байт в байт; если отличаются, печатается
заметка. Если программа просит не то, что записано следующим, — R0017. Запись и повтор есть и в Python-бэкендах
(`klar run --record`, `klar replay`), и в native-коде (`klarc run --record`, `klarc replay`): формат записи один, и
запись одного инструмента повторяется другим.

Неизвестное право — ошибка запуска (код выхода 2). Без `--allow` проверки нет: программа может всё, что объявляют её
`uses`. В native-коде права встраиваются в исполняемый файл.

## 10. Реализации и их соответствие

* `klar` (Python) — эталонные интерпретатор и проверка типов, компилятор в машинный код и инструменты.
* `klarc` (Klar, `compiler/`) — тот же язык и те же инструменты, написанные на Klar; собирает сам себя
  (`build.sh`, `build.bat`).

`tests/selfhost.py` проверяет, что `klarc` выдаёт байт в байт те же исполняемые файлы и те же диагностики, что `klar`;
`tests/bootstrap.py` — что `klarc` воспроизводит себя; `tests/native_diff.py` — что машинный код ведёт себя как
интерпретатор (на Windows — под wine, на AArch64 — под qemu, на macOS — под эмулятором `tests/macho_run.py`).
