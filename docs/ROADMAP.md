# Klar после 1.0 — план

Klar уже ловит типичные ошибки ИИ до запуска. Дальше главное — дать агенту прямой доступ к инструментам, безопасно
запускать написанный им код и измерять, насколько хорошо модели пишут на Klar. Пункты идут по фазам; у каждого —
критерий готовности. Статус: ✅ сделано · 🔄 в работе · ⬜ не начато.

## Фаза 5 — доказать тезис, а не наращивать фичи

Главный тезис Klar: на нём ИИ пишет правильный код чаще, чем на популярных языках. Пока его подтверждают задачи и
эталонные решения, написанные нами же, — язык подогнан под собственный экзамен. Здесь тезис проверяется на чужих
данных, и дальнейший план решают результаты. Отчёт — числами и воспроизводимыми скриптами; отрицательный результат —
тоже результат.

| # | Что | Готово, когда | Статус |
|---|---|---|---|
| 18 | **Сырые данные об ошибках ИИ**: реальные провалы агентов (публичные траектории SWE-bench), BugsInPy/Defects4J, нефильтрованные ответы нескольких моделей (Claude, GPT, Gemini, открытые), которым дана только `klar spec` | таксономия ошибок, размеченная двумя независимыми разметчиками (согласие — каппа Коэна); видно, какие ошибки Klar ловит, а какие нет | ⬜ |
| 19 | **Чужие задачи вместо своих**: HumanEval и MBPP на Klar по методике MultiPL-E, плюс LiveCodeBench; гипотезы и метрики фиксируются до прогона (предрегистрация) | один харнесс гоняет Klar, Python, TypeScript, Rust на одних задачах | ✅ `bench/ai/build_suites.py`: HumanEval 154/161 и MBPP 334/400 задач, 2 111 тестов, каждый проверен каноническим решением; `llm_bench.py --suite`, `--validate`: все тесты типизируются во всех трёх языках |
| 20 | **Прогон и метрики**: pass@1 / pass@k, **repair rate** — доля исправлений после одного ответа компилятора (главный козырь Klar), токены решения, токены спецификации, нужные модели, которая Klar не видела в обучении (реальные токенизаторы) | таблица по моделям × языкам с доверительными интервалами (бутстреп) и парными тестами (Мак-Нимар); отчёт в `bench/ai/results` | 🔄 прогон агентами (Sonnet, Haiku; `bench/ai/agent_bench.py`): 486 задач × 3 языка, итоги в [bench/ai/README.md](../bench/ai/README.md#агенты-в-роли-модели-agent_benchpy-результаты). HumanEval насыщен; с первой попытки Klar 97,7% против 99,4% у Python (p = 0,02), главная причина — E0208. После исправлений (умный E0208, `{"a": 1}`, `=> {`, литералы) Haiku: свои задачи 91,7% → 100%, HumanEval+ 96,1% → 96,8%, время сравнялось с Python. Трудный набор (`--suite hard`, 20 задач): Haiku — 19/20 с первой попытки на всех трёх языках, у Klar ни одной ошибки компиляции, но токенов на 60% больше, чем у Python. Без справки (`haiku-nospec`): 15/20 и 19/20 — компилятор учит языку за одну-две попытки; лексер теперь сообщает все свои ошибки сразу. Рефакторинг (`refactor_bench.py`, 4 программы из 4 модулей): 4/4 на всех языках, Klar +34% токенов; программы этого размера модель читает целиком, нужны большие. Оценка `bench/ai/syntax_cost.py`: синтаксис даёт каждому изменению не больше 2,8% токенов решения, зато `klar spec` стал на 32% короче (сигнатуры std — по `klar doc`), эффект ещё не измерен. Дальше: повторный прогон, модели других семейств через API |
