# Klar после 1.0 — план

Klar уже ловит типичные ошибки ИИ до запуска. Дальше главное — дать агенту прямой доступ к инструментам, безопасно
запускать написанный им код и измерять, насколько хорошо модели пишут на Klar. Пункты идут по фазам; у каждого —
критерий готовности. Статус: ✅ сделано · 🔄 в работе · ⬜ не начато.

## Фаза 1 (1.1) — агент работает с Klar напрямую

| # | Что | Готово, когда | Статус |
|---|---|---|---|
| 1 | **Windows без Python до конца**: `run_capture` на Windows (CreateProcess + pipe), git-зависимости и `klarc add/fetch` там же | `run_capture` даёт тот же результат, что на Linux (тест под wine), `klarc fetch` работает на Windows | ✅ |
| 2 | **`klar mcp`** — MCP-сервер (stdio, JSON-RPC): инструменты `check`, `test`, `dev`, `patch`, `eval`, `doc`, `outline`, `refs`, `explain`, `spec`; то же в `klarc mcp` без Python | агент (Claude Code) по MCP пишет, правит и тестирует программу; ответы `klar mcp` и `klarc mcp` совпадают (`tests/selfhost.py`) | ✅ |
| 3 | **`klar context <имя>`** — минимальный контекст для модели: сигнатура, документация, примеры, используемые типы, тесты и вызывающие, с лимитом токенов | для любой функции репозитория — один ответ ≤ лимита, достаточный для правки без чтения файлов | ✅ |
| 4 | **Песочница по эффектам**: `klar run --allow fs:./data,proc:git,net` — эффекты становятся правами и при запуске; рантайм отказывает в вызове вне разрешённого (R-код с объяснением) | код без `--allow fs` не читает файлы даже через `run_command`; тесты на каждое право во всех бэкендах | ✅ |

## Фаза 5 — доказать тезис, а не наращивать фичи

Главный тезис Klar: на нём ИИ пишет правильный код чаще, чем на популярных языках. Пока его подтверждают задачи и
эталонные решения, написанные нами же, — язык подогнан под собственный экзамен. Здесь тезис проверяется на чужих
данных, и дальнейший план решают результаты. Отчёт — числами и воспроизводимыми скриптами; отрицательный результат —
тоже результат.

| # | Что | Готово, когда | Статус |
|---|---|---|---|
| 18 | **Сырые данные об ошибках ИИ**: реальные провалы агентов (публичные траектории SWE-bench), BugsInPy/Defects4J, нефильтрованные ответы нескольких моделей (Claude, GPT, Gemini, открытые), которым дана только `klar spec` | таксономия ошибок, размеченная двумя независимыми разметчиками (согласие — каппа Коэна); видно, какие ошибки Klar ловит, а какие нет | ⬜ |
| 19 | **Чужие задачи вместо своих**: HumanEval и MBPP на Klar по методике MultiPL-E, плюс LiveCodeBench; гипотезы и метрики фиксируются до прогона (предрегистрация) | один харнесс гоняет Klar, Python, TypeScript, Rust на одних задачах | ⬜ |
| 20 | **Прогон и метрики**: pass@1 / pass@k, **repair rate** — доля исправлений после одного ответа компилятора (главный козырь Klar), токены решения, токены спецификации, нужные модели, которая Klar не видела в обучении (реальные токенизаторы) | таблица по моделям × языкам с доверительными интервалами (бутстреп) и парными тестами (Мак-Нимар); отчёт в `bench/ai/results` | ⬜ (нужны ключи API) |
| 21 | **Абляции решений дизайна**: запрет затенения, обязательные именованные аргументы, эффекты `uses`, контракты, отсутствие `unwrap`, проверка деления — по одному выключаются | у каждого решения измерен вклад (знак и величина); решения без пользы предложены к удалению | ⬜ |
| 22 | **Сравнение с конкурентами** на тех же задачах: MoonBit (прямо называет себя AI-friendly), Gleam, Koka (эффекты), Dafny (контракты), Elm (сообщения об ошибках) | таблица «в чём Klar лучше или хуже каждого» по данным, а не по спискам фич | ⬜ |
| 23 | **Формальное ядро типов**: правила типизации ядра (PLT Redex, K или Lean); проверка корректности «прошло проверку — не падает так-то» на миллионах случайно сгенерированных программ (в духе Csmith/QuickChick); фаззинг парсера | механизированная модель ядра; ноль контрпримеров на большом прогоне; найденные баги исправлены | ⬜ |
| 24 | **Модель угроз песочницы**: агент запускает недоверенный код — ревью `--allow`, `run_command`, путей и ссылок | список угроз с тестом на каждую | ⬜ |
| 25 | **Люди и внешняя проверка**: небольшое исследование — как быстро человек находит ошибку в коде ИИ на Klar и на Python; сторонний человек или агент пишет на Klar настоящую программу; открытый харнесс для внешней репликации, доклад на PLATEAU или воркшопе по LLM для кода | есть внешний результат, который можно перепроверить без нас | ⬜ |
| 26 | **ROADMAP по данным**: по итогам 18–25 пересмотреть фазы 1–4 | план опирается на числа из отчёта | ⬜ |

## Фаза 6 — Klar без Python

Цель — собрать, проверить и использовать Klar без Python, а не «больше строк на Klar» (GitHub Languages не знает
`.klar` и тут ни при чём). Сейчас каждая возможность пишется дважды: `klar/*.py` и `compiler/*.klar`.

| # | Что | Готово, когда | Статус |
|---|---|---|---|
| 27 | **Инвентарь Python-кода из первоисточников**: `git ls-files`, граф импортов, coverage по всем тестам, `vulture`; каждый модуль — путь пользователя / оракул / тестовая обвязка / заблокирован (с причиной); цена двойной поддержки по `git log` (какие `.py` и `.klar` меняются вместе) | таблица по каждому модулю и число совместных изменений | ⬜ |
| 28 | **Решение по эталону на Python**: заморозить как оракул для дифференциальных тестов или убрать из сборки (как Go 1.5 убрал C); аргументы и риски | решение принято и записано | ⬜ |
| 29 | **Автоматическая матрица `klar` ↔ `klarc`**: команды и флаги из argparse против разбора аргументов `klarc` | скрипт в `tests/`, 100 % пользовательских команд есть в `klarc` | ⬜ |
| 30 | **Перенос по одной команде** (strangler fig): готово, когда команда в матрице, проходит дифференциальные тесты и бюджет времени/памяти; Python-версия удаляется в том же коммите; пробелы языка, найденные при переносе, — отдельными пунктами сюда | раннеры бенчмарков ✅, запись/повтор ✅, остальное по инвентарю | 🔄 |
| 31 | **Сила проверок**: генератор случайных программ для дифференциального фаззинга, мутационное тестирование компилятора на Klar, неподвижная точка самосборки и DDC (Уилер), пока Python есть как независимый компилятор | 0 расхождений на N программах, отчёт о мутационном балле | ⬜ |

| 33 | **CI без Python**: контейнер без `python3` — seed → `build.sh` → все тесты; то же на Windows, macOS, arm64; релизные бинарники и путь установки для новичка | задача CI зелёная; человек с чистой машины проходит GUIDE с релизного бинарника | ⬜ |
