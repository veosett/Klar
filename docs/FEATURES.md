# Анализ языков и список функций Klar

Для каждой возможности ниже указано, как её решают основные языки, чем это удобно или неудобно для ИИ и что берёт Klar.

**Языки:** Python, JavaScript/TypeScript, Java/C#, Go, Rust, Kotlin/Swift, Haskell/OCaml/F#, Elixir, Zig.

**Как оцениваем.** Модель пишет код токен за токеном, видит только контекстное окно и учится на смеси всех языков. Поэтому возможность хороша для ИИ, если она:
1. **локальна** — смысл виден на месте, без поиска определения в другом файле;
2. **однозначна** — есть один способ записи, а не пять;
3. **проверяема** — ошибку ловит компилятор или тест, а не пользователь;
4. **знакома** — похожа на то, что модель видела чаще всего;
5. **устойчива к частичным правкам** — вставка или удаление строк не ломает соседний код.

Обозначения: ✅ взять как есть · 🔄 адаптировать · ❌ отказаться · `0.1` / `0.2` / `0.3` / `план` — версия, в которой функция реализована или запланирована.

## 1. Синтаксис

| Возможность | Где есть | Для ИИ | Решение Klar |
|---|---|---|---|
| Значимые отступы | Python, F#, Haskell | ломаются при вставке кусков и в diff'ах, смешение табов и пробелов | ❌ → фигурные скобки |
| `{ }` + `;` | C, Java, JS, Rust | `;` — постоянный источник мелких ошибок, JS ещё и вставляет их автоматически (ASI) | 🔄 скобки есть, `;` нет: конец инструкции — перевод строки `0.1` |
| Слова `and/or/not` | Python | читаются однозначно, не путаются с `&`/`|` | ✅ `0.1`, `&&`/`||`/`!` — ошибка с подсказкой |
| Тернарный `a ? b : c` | C, JS, Java | конфликтует с `?` для ошибок, вкладывается нечитаемо | ❌ → `match cond { true => a, false => b }` `0.1` |
| Строковая интерполяция | Python f"", JS \`${}\`, Kotlin "$x" | убирает конкатенацию с преобразованием типов | ✅ `"{expr}"` `0.1` |
| Цепочки через перенос `.` | Kotlin, Swift, Rust | естественны для коллекций | ✅ `0.1` |
| Единый форматтер | Go `gofmt`, Rust `rustfmt` | один канонический вид → меньше вариативности в обучении и правках | ✅ `klar fmt` `план` |

## Итоговый список функций Klar

### Реализовано в 0.1
Скобки без `;` · `and/or/not` · интерполяция · статические типы с выводом · дженерик-функции · `Option`/`Result`/`?` · запрет игнорировать `Result` · неизменяемость + `with` · `let`/`var` · запрет затенения · именованные аргументы (≥3) · UFCS · лямбды · `requires`/`ensures` · эффекты `uses` · исчерпывающий `match` · `test` и `assert` с обеими сторонами · `Int` без переполнения · JSON-диагностики, `explain`, `spec`, `ast`.

### Реализовано в 0.2
1. Обобщённые записи и enum: `type Pair[A, B]`, `enum Tree[T]`
2. Алиасы типов: `type UserId = Int`
3. Константы: `const MAX_USERS: Int = 100`
4. Guards в `match`: `n if n > 0 => ...`
5. Модули: `use geometry.{Point, area}`, модуль = файл, ошибка на циклы
6. Прелюдия, написанная на самом Klar: `Pair`, `Entry`, `Indexed`, `PI`, `E`
7. Stdlib: `enumerate`, `zip`, `flat_map`, `flatten`, `unique`, `partition`, `group_by`, `chunks`, `min/max`, `min_by/max_by`, `insert`, `remove_at`; `Map.entries/map_values/update/filter/merge`; `Str.lines/pad_left/pad_right/trim_start/trim_end/count/reverse`; `Float.pow/fixed/sin/cos/ln/exp`
8. Файлы и аргументы: `read_file`, `write_file`, `file_exists` (эффект `fs`), `cli_args()`
9. `dbg(x)` и `todo("...")`
10. Doc-тесты `/// >>> ...`
11. Property-тесты `property "..." (x: T) { ... }` с генерацией входов и сжатием контрпримера

12. `klar dev` (один шаг цикла ИИ), `klar fix`, `klar profile`, бэкенд Klar → Python

### Реализовано в 0.3 (эта итерация)
1. Собственный компилятор Klar → машинный код x86-64: KIR, оптимизатор, линейный регистровый аллокатор, ассемблер
2. Собственный линкер: ELF64 для Linux (системные вызовы, без libc) и PE32+ для Windows (только KERNEL32.dll)
3. Рантайм на системном Klar: аллокатор, подсчёт ссылок, большие числа, Float с кратчайшей печатью, строки UTF-8, List, Map
4. `klar build` с кросс-компиляцией, кэш сборок, `klar run` по умолчанию через native
5. Ошибки времени выполнения и трассировки идентичны интерпретатору; дифференциальные тесты на Linux и Windows
